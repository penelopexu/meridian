# 域名与部署

这份文档回答三个问题：**放到哪**、**怎么放**、**免费域名怎么弄**。

---

## 先说结论

| 方案 | 网址 | 要不要审批 | 多久能用 |
|---|---|---|---|
| GitHub Pages（已配好） | `penelopexu.github.io/meridian` | 不用 | 推送后约 1 分钟 |
| Cloudflare Pages | `meridian.pages.dev` | 不用 | 连上仓库后约 2 分钟 |
| js.org 免费域名 | `meridian.js.org` | **要**，且有被拒风险 | 通常 24 小时内 |

**建议顺序**：先把 GitHub Pages 跑通（工作流已经写好了，推上去就自动部署），确认能访问；
再决定要不要折腾域名。域名是锦上添花，不是发布的前提。

---

## 一、GitHub Pages（最省事，已配置完成）

仓库里的 `.github/workflows/pages.yml` 已经写好，推送到 `main` 分支就会自动构建并部署 `dist/pwa/`。

你只需要在网页上打开一次开关：

1. 进仓库 → **Settings** → 左侧 **Pages**
2. **Source** 选 **GitHub Actions**（不是 "Deploy from a branch"）
3. 保存

推一次代码，等 Actions 跑完，网址就是 `https://penelopexu.github.io/meridian/`。

---

## 二、Cloudflare Pages（想要自定义响应头就用这个）

GitHub Pages 有个改不了的限制：**不支持自定义 HTTP 响应头**。
所以仓库里的 `public/_headers`（安全头 + Service Worker 缓存策略）在 GitHub Pages 上会被忽略，
只有 Cloudflare Pages 和 Netlify 认它。

页面里那份 `<meta>` 形式的 CSP 是为此准备的兜底——两边不是重复，是互为备份。

### 接入步骤

1. 注册 <https://dash.cloudflare.com>（免费账户即可）
2. 左侧 **Workers & Pages** → **Create** → **Pages** → **Connect to Git**
3. 授权 GitHub，选 `meridian` 仓库
4. 构建设置填：

   | 字段 | 填什么 |
   |---|---|
   | Framework preset | None |
   | Build command | `node build.mjs` |
   | Build output directory | `dist/pwa` |
   | Root directory | 留空 |

   环境变量不需要配。这个项目零依赖，也不需要任何密钥。

5. 点 **Save and Deploy**

完成后网址是 `https://meridian.pages.dev`。以后每次推送 `main` 都会自动重新部署。

> **顺带一提**：Cloudflare Pages 免费版每月 500 次构建，对个人项目远远够用。

## 三、js.org 免费域名

### 丑话说在前面

js.org 的内容规则写得很明确：

> Websites must be **directly** related to the JavaScript ecosystem/community
> (such as NPM packages / JS tools, not personal pages / portfolios)
>
> 网站必须**直接**与 JavaScript 生态/社区相关（比如 NPM 包、JS 工具，
> 而不是个人主页或作品集）

**天时是一个日历天气应用，不是 JS 库或开发工具。** 这条能不能过，取决于审核者怎么看：

- 有利的一面：它是一个零依赖的纯 JavaScript 项目，源码本身就是给人读和改的，
  仓库里有完整的 CONTRIBUTING、测试套件和多语言架构，不是占位页面
- 不利的一面：它面向的是普通用户而非开发者，严格讲属于"应用"而非"JS 工具"

我的判断是**五五开**。值得试，但别把发布计划押在它上面。被拒了也不影响任何事，
`penelopexu.github.io/meridian` 和 `meridian.pages.dev` 都是能长期用的正经网址。

### 如果要申请

**第 1 步**：先确保站点已经上线且有实质内容。js.org 明确拒绝占位页。
（我们这个不缺内容，直接进下一步。）

**第 2 步**：想好子域名。按规则可以用你的用户名或仓库名，
所以 `meridian.js.org` 或 `penelopexu.js.org` 都行。推荐前者。

**第 3 步**：给站点绑定这个自定义域名。**这一步有个坑**——

> js.org 官方文档原话：用 GitHub Actions 工作流发布时，**仓库里的 `CNAME` 文件不会生效**，
> 必须在仓库设置里填。

我们正是用工作流发布的，所以：

- **不要**在仓库里建 `CNAME` 文件
- 去 **Settings → Pages → Custom domain**，填 `meridian.js.org`，保存

（如果你后来改用 Cloudflare Pages 托管，则是在 Pages 项目里
 **Custom domains → Set up a custom domain** 填这个域名。）

**第 4 步**：给 <https://github.com/js-org/js.org> 提 PR。

具体做法：Fork 那个仓库 → 编辑 `cnames_active.js` → 按字母顺序插入一行：

```js
  "meridian": "penelopexu.github.io/meridian",
```

注意值里**不带** `https://`，也**不带**结尾斜杠。
提 PR 时按它的模板把项目说明写清楚——这一步是审核者判断"够不够 JS 相关"的主要依据，
值得多写两句：强调零依赖、纯 JavaScript 实现、自研农历与节气天文算法、有测试和文档。

**第 5 步**：等。通常 24 小时内合并，合并后再等 DNS 生效（一般几分钟到几小时）。

### 如果被拒了，还有这些

| 服务 | 域名样子 | 备注 |
|---|---|---|
| Cloudflare Pages | `meridian.pages.dev` | **零审批，立刻可用**，最省心 |
| GitHub Pages | `penelopexu.github.io/meridian` | 零审批，已配好 |
| [is-a.dev](https://github.com/is-a-dev/register) | `meridian.is-a.dev` | 面向开发者，同样是提 PR，规则比 js.org 宽松 |
| [eu.org](https://nic.eu.org) | `meridian.eu.org` | 完全免费的正经二级域名，但人工审核，可能等好几周 |

## 四、一个绕不开的现实问题

GitHub Pages 和 Cloudflare Pages 在中国大陆的访问都**不稳定**——
时通时不通，跟运营商和时段有关。这不是配置问题，改什么都解决不了。

这也正是这个项目坚持产出**单文件版**的原因：

`dist/天时-单文件.html` 是一个 401 KB 的独立文件，字体、样式、脚本、
144 座城市离线库、2885 条中国区县映射、1900–2100 农历表全部内嵌。
双击就能用，拷到 U 盘也能用，发微信给朋友也能用。日历、农历、节气、
节假日、阴阳历互转这些功能完全不依赖网络——只有天气需要联网。

**所以发布策略是两条腿走路**：网页版给能访问的人，单文件版挂在 GitHub Release 里给所有人。

---

## 五、发一个 Release

网页部署好之后，把单文件版挂上去：

1. 本地跑 `npm run build`
2. 仓库页面 → 右侧 **Releases** → **Create a new release**
3. **Tag**：`v0.1.0`（点 "Create new tag on publish"）
4. **Title**：`v0.1.0 — 首个公开版本`
5. 正文从 `CHANGELOG.md` 里抄
6. 把 `dist/天时-单文件-带图标.html` 拖进 **Attach binaries** 区域
7. **Publish release**

这样别人不用会 git、不用装 Node，点一下就能下载使用。
